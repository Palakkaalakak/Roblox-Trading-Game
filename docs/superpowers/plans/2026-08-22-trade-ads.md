# Trade Ads Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the existing board "Trades" tab into a Trade Ads system with presence-tied lifetimes, server/global scopes, per-player slot limits, and paid placement that never gates trading.

**Architecture:** Nearly all storage and sort machinery already exists as scaffolding in `TradeBoardService.luau` (`boostTier`, `bumpedAt`, `expiresAt`, `boostListing`, and a `listingOrder` that already sorts boosted first). The work is: extract the decidable rules into a pure, testable module; route server-scoped ads to the existing server-local `memBoard` and global ones to the existing MemoryStore map; piggyback expiry refresh on the board sweep that already runs; wire a purchase flow through the existing `ProductService.registerDevProduct` extension point; and build the UI.

**Tech Stack:** Luau (`--!strict`), Rojo 7.7.0, Roblox MemoryStore + DataStore via `StoreAdapters`, no external packages. Tests are assert-based modules under `src/server/Tests/` discovered automatically by `TestRunner`.

**Spec:** `docs/superpowers/specs/2026-08-22-trade-ads-design.md`

## Global Constraints

- Luau `--!strict` at the top of every new file.
- **Payment buys position and duration only.** Posting, browsing, and accepting stay free for everyone. No code path may gate a trade action on payment.
- **The refresh writes `expiresAt` only, never `bumpedAt`.** This is the decay invariant: staying online keeps an ad alive, not on top.
- Write budget: roughly one small store write per ad per hour, for online posters only. No per-action or per-frame write paths — see the syndicate write-storm regression fixed in `df516be`.
- All Roblox product ids are `MonetizationConfig.PlaceholderProductId` for now. Real ids at publish.
- **The boost SKU rides in the purchase intent, not the product id.** `registerDevProduct` refuses duplicate ids, and with every SKU on the placeholder only the first would register.
- Featured is excluded from gamepasses — only 3 slots per scope, and a permanent pass would let one player squat the pool.
- Slot limit per scope = `BaseSlotsPerScope + profile.TradeAds.extraSlots`.
- Bots stay server-scoped (they live in server-local `memBoard`). The scope filter therefore defaults to `THIS SERVER` so the board always looks populated.
- Match the surrounding comment density and naming. This codebase explains *why* in comments, not *what*.

```lua
--!strict
-- Trade ad rules and paid placement catalogue.
--
-- Two scopes with deliberately different economics:
--   * SERVER ads live in the server-local memBoard and die when the poster
--     leaves. They are cheap to boost because the audience is one server --
--     but whoever answers is online right now, so the trade settles at once.
--   * GLOBAL ads live in the MemoryStore map, reach the whole experience and
--     outlive the poster's session by GlobalGraceSeconds. Boosting them costs
--     more because the reach is the whole game.
--
-- Payment buys POSITION and DURATION. It never gates posting, browsing or
-- accepting -- that rule is load-bearing, not decoration.

local TradeAdConfig = {
	Scopes = {
		Server = "server",
		Global = "global",
	},

	-- Free allowance per scope. A player therefore starts with 3 server ads
	-- AND 3 global ads, not 3 in total.
	BaseSlotsPerScope = 3,
	-- Purchased slots stack on top, per scope. Capped so a single buyer can't
	-- crowd the whole board out of the free players' reach.
	MaxExtraSlots = 27,

	-- How long an ad outlives its poster's session. Server ads go the instant
	-- the poster leaves (their store is that server's memory); global ads get
	-- a grace window so a disconnect doesn't destroy a live negotiation.
	ServerGraceSeconds = 0,
	GlobalGraceSeconds = 2 * 3600,

	-- The sweep pushes an ad's death clock only when it is inside this window,
	-- so a long AFK session costs about one small write per ad per hour rather
	-- than one per sweep.
	RefreshThresholdSeconds = 3600,

	-- Scarce on purpose: scarcity is what makes the strip worth buying, and
	-- what stops it becoming a second feed.
	FeaturedSlotsPerScope = 3,

	BoostTier = {
		None = 0,
		Priority = 1,
		Featured = 2,
	},
}
```

```lua
--!strict
-- Pure decision logic for trade ads. No store calls, no Players lookups --
-- everything here is a function of its arguments, so it can be unit tested
-- without a running game, and so the same answers hold on every server.

local ReplicatedStorage = game:GetService("ReplicatedStorage")
local TradeAdConfig = require(ReplicatedStorage.Shared.Config.TradeAdConfig)

local TradeAdRules = {}

-- Free allowance plus whatever the player bought, clamped so one buyer can't
-- crowd everyone else off the board.
function TradeAdRules.slotLimit(extraSlots: number): number
	local extra = math.clamp(extraSlots or 0, 0, TradeAdConfig.MaxExtraSlots)
	return TradeAdConfig.BaseSlotsPerScope + extra
end

function TradeAdRules.canPost(openCount: number, extraSlots: number): boolean
	return openCount < TradeAdRules.slotLimit(extraSlots)
end

function TradeAdRules.graceFor(scope: string): number
	if scope == TradeAdConfig.Scopes.Server then
		return TradeAdConfig.ServerGraceSeconds
	end
	return TradeAdConfig.GlobalGraceSeconds
end

-- Only worth a write once the ad is actually close to dying. Checking on every
-- sweep but writing rarely is what keeps this to roughly one write per ad per
-- hour instead of one per sweep.
function TradeAdRules.shouldRefresh(listing: any, now: number): boolean
	local expiresAt = listing.expiresAt
	if expiresAt == nil then
		return true
	end
	return (expiresAt - now) < TradeAdConfig.RefreshThresholdSeconds
end

-- The new death clock. Note what this does NOT return: a bumpedAt. Callers
-- assign this to expiresAt and nothing else -- staying online keeps an ad
-- alive, it does not keep it on top.
function TradeAdRules.refreshedExpiry(scope: string, now: number): number
	local grace = TradeAdRules.graceFor(scope)
	-- Server ads have no grace, so without a floor they would expire the moment
	-- the sweep touched them. The refresh window is that floor: it is exactly
	-- how long we can promise before the next sweep gets another chance.
	return now + math.max(grace, TradeAdConfig.RefreshThresholdSeconds * 2)
end

-- A gamepass lifts every ad its owner holds; a purchased tier lifts one ad.
-- Take the higher so buying a one-off never downgrades a pass holder.
function TradeAdRules.effectiveTier(listing: any): number
	local tier = listing.boostTier or TradeAdConfig.BoostTier.None
	local perks = listing.perks
	if perks and perks.priority and tier < TradeAdConfig.BoostTier.Priority then
		tier = TradeAdConfig.BoostTier.Priority
	end
	return tier
end

-- How many featured slots are still buyable in this scope. Expired ads free
-- their slot automatically, so nothing has to be reclaimed on a timer.
function TradeAdRules.featuredOpenSlots(listings: { any }, scope: string, now: number): number
	local used = 0
	for _, l in listings do
		if
			l.scope == scope
			and (l.boostTier or 0) >= TradeAdConfig.BoostTier.Featured
			and (l.expiresAt == nil or l.expiresAt > now)
		then
			used += 1
		end
	end
	return math.max(0, TradeAdConfig.FeaturedSlotsPerScope - used)
end

-- Feed order: paid tier first, then most recently bumped, then id (ids are
-- time-prefixed, so id order is creation order and the sort is total).
function TradeAdRules.order(a: any, b: any): boolean
	local aTier, bTier = TradeAdRules.effectiveTier(a), TradeAdRules.effectiveTier(b)
	if aTier ~= bTier then
		return aTier > bTier
	end
	local aBump = a.bumpedAt or a.createdAt or 0
	local bBump = b.bumpedAt or b.createdAt or 0
	if aBump ~= bBump then
		return aBump > bBump
	end
	return (a.id or "") > (b.id or "")
end

return TradeAdRules
```

```lua
-- Push one listing's death clock if it is close to expiring. Returns whether
-- anything changed, so the caller only spends a store write when it did.
--
-- This deliberately assigns expiresAt and NOTHING else. Moving bumpedAt here
-- would hand an AFK player permanent rank one for free and make every paid
-- placement worthless -- the invariant is covered by a test for that reason.
function TradeBoardService.applyPresenceRefresh(listing: any, now: number): boolean
	if listing.status ~= "open" then
		return false
	end
	if not TradeAdRules.shouldRefresh(listing, now) then
		return false
	end
	listing.expiresAt = TradeAdRules.refreshedExpiry(listing.scope or TradeAdConfig.Scopes.Global, now)
	return true
end

-- Walk the board once and keep alive every ad whose poster is on THIS server.
-- There is no by-poster index, so a per-player loop would mean a full scan per
-- player; piggybacking the scan the sweep already performs costs nothing extra,
-- and each server naturally refreshes only its own players' ads.
function TradeBoardService.refreshPresenceExpiry()
	local now = os.time()
	for _, l in TradeBoardService.rawOpenListings() do
		if l.posterId > 0 and Players:GetPlayerByUserId(l.posterId) ~= nil then
			if TradeAdRules.shouldRefresh(l, now) then
				mutate(l.id, function(live)
					if not TradeBoardService.applyPresenceRefresh(live, os.time()) then
						return nil
					end
					live.v += 1
					return live
				end)
			end
		end
	end
end
```

```lua
-- Decide what a paid boost does when its receipt lands. Split out from the
-- receipt handler so it can be tested without a purchase: the money has already
-- changed hands by the time this runs, so "do nothing" is never an answer.
function TradeBoardService.resolveBoost(profile: any, listing: any?, sku: any, openFeatured: number): string
	if listing == nil or listing.status ~= "open" then
		return "credit" -- the ad expired or settled while the purchase was in flight
	end
	if listing.scope ~= sku.scope then
		return "credit" -- a server SKU must not buy global reach at the server price
	end
	if sku.tier >= TradeAdConfig.BoostTier.Featured and openFeatured <= 0 then
		return "credit" -- the strip filled up mid-purchase; bank it rather than oversell
	end
	return "apply"
end

local function bankCredit(profile: any, skuId: string)
	profile.TradeAds = profile.TradeAds or { extraSlots = 0, credits = {} }
	profile.TradeAds.credits = profile.TradeAds.credits or {}
	profile.TradeAds.credits[skuId] = (profile.TradeAds.credits[skuId] or 0) + 1
end

	TradeBoardService.boostListing(listingId, sku.tier, sku.seconds > 0 and sku.seconds or nil)
```

```lua
-- Percentage the poster is giving away, from the viewer's perspective:
-- positive means the poster's side is worth more. Guarded against an empty
-- want side, which is a legitimate "make me an offer" ad, not an error.
function TradeBoardService.valueDelta(giveValue: number, wantValue: number): number
	if giveValue <= 0 and wantValue <= 0 then
		return 0
	end
	local base = math.max(wantValue, 1)
	return math.floor(((giveValue - wantValue) / base) * 100 + 0.5)
end
```
